# 研究室見学カレンダー

研究室見学の予定を、各自が入手したJSONファイルから読み込んで確認する静的Webページです。週ごとの日程、研究室や分野による絞り込み、参加候補の確認に使えます。公開するページには実際の研究室名や見学日程を同梱せず、初回はデータ未読込の状態で開きます。

公開先リポジトリ: [samiosu/kenkyuusitu_calender](https://github.com/samiosu/kenkyuusitu_calender)

## 使い方

1. ページを開き、「JSONを読み込む」から手元の予定ファイルを選びます。
2. 週を移動し、研究室名や分野で予定を絞り込みます。「表示する研究室」を開いてチェックを外すと、研究室ごとに予定を非表示にできます。「すべて表示／すべて非表示」でまとめて切り替えることもできます。
3. 気になる見学を参加候補に追加し、予定の重なりを確認します。
4. 必要なら、選んだ候補をICS形式で書き出し、普段のカレンダーへ取り込みます。

実際の予定がなくても、サンプル表示から操作を試せます。サンプルの研究室・会場・日程はすべて架空です。見学への参加登録や予約を行う機能はありません。予約が必要な場合は、配布元の案内を確認してください。

分野のチェックを切り替えると、その分野に属する研究室もまとめてON／OFFになります。研究室を個別に選択すると、分野側も連動し、一部だけ選択されている場合は横線を表示します。すべて非表示の分野でも、研究室を1つONにすればその研究室の予定が表示されます。

研究室の表示設定は、週間表示・一覧・マイプラン表示と、検索の絞り込みに共通で反映します。非表示にしても保存済みの見学候補は削除しません。重複警告とICS出力は、表示条件にかかわらず保存した候補全体が対象です。「絞り込みをリセット」またはサイドバーの「リセット」で、研究室もすべて表示に戻ります。

## データの扱い

- ファイルはブラウザー内で読み取ります。選択したJSONをサーバーやGitHubにアップロードする処理はありません。
- JSON本体、研究室名、日程はブラウザーの永続ストレージに保存しません。再読み込み後はJSONを選び直してください。
- 参加候補の予定IDと、非表示にする研究室のIDだけを、そのブラウザーの`localStorage`に保存します。同じJSONを再度読み込むと候補と表示設定を復元できます。IDには個人名や機密情報を含めないでください。
- 候補と表示設定の保存先は、全予定のID・日付・開始時刻・終了時刻から計算した識別値で分かれます。それらを変更したJSONは別の予定データとして扱われるため、候補と表示設定を選び直してください。
- アクセス解析、外部フォント、外部CDNは使いません。任意の研究室リンクを開くと、そのリンク先へアクセスします。
- 読み込めるJSONはUTF-8、最大1 MiB（1,048,576バイト）です。URLからの取得には対応せず、手元のファイルを選ぶ方式です。

自分で書き出したICSファイルには、選択した研究室名・日時・会場などが含まれます。端末の外へ共有するときは、元データの利用条件を確認してください。

この設計は、公開リポジトリに実データを含めずに使うためのものです。掲載・配布の可否や必要な許諾は、データの入手元・利用条件に従って確認してください。JSONの配布方法は、このWebページとは別に用意します。

実データはリポジトリの外に保管するか、`private/`・`data/`・`*.local.json`などのGit管理対象外の場所へ置いてください。`.gitignore`は、すでにコミットされたファイルや過去の履歴からデータを削除するものではありません。

## ローカルで動かす

[Node.js](https://nodejs.org/) 22以上を使用します。追加パッケージのインストールは不要です。

```sh
npm start
```

ブラウザーで <http://127.0.0.1:4173> を開きます。Windows PowerShellで`npm`の実行が制限される場合は、`npm.cmd start`を使ってください。`index.html`を直接開く方式ではJavaScriptモジュールやサンプル取得が制限されるため、ローカルサーバーを使います。

ポートを変更する場合（PowerShell）:

```powershell
$env:PORT = '4180'
npm.cmd start
```

サーバーは`127.0.0.1`だけで待ち受け、公開用ファイルだけを配信します。プレビューの停止は`Ctrl+C`です。

## JSONの形式

最小構成の例です。ファイル名は任意ですが、実データには`schedule.local.json`のような名前を推奨します。

```json
{
  "version": 1,
  "title": "研究室見学の予定",
  "updatedAt": "2026-10-15",
  "labs": [
    {
      "id": "example-lab",
      "name": "架空研究室A",
      "category": "情報",
      "sessions": [
        {
          "id": "visit-1",
          "date": "2026-10-19",
          "start": "13:00",
          "end": "14:00"
        }
      ]
    }
  ]
}
```

| 対象 | 項目 | 必須 | 内容 |
| --- | --- | --- | --- |
| 全体 | `version` | ○ | 数値の`1` |
| 全体 | `title` | ○ | タイトル。120文字以内 |
| 全体 | `updatedAt` | ○ | 更新日`YYYY-MM-DD`、またはタイムゾーン付きISO日時（例:`2026-10-15T09:00:00+09:00`） |
| 全体 | `labs` | ○ | 研究室の配列。最大100件 |
| 研究室 | `id` | ○ | 全研究室内で重複しないID |
| 研究室 | `name` | ○ | 研究室名。120文字以内 |
| 研究室 | `category` | ○ | 分野名。60文字以内 |
| 研究室 | `description` | 任意 | 研究内容など。2,000文字以内 |
| 研究室 | `url` | 任意 | 研究室のHTTPS URL。2,048文字以内。空文字も可 |
| 研究室 | `sessions` | ○ | 見学日程の配列。全研究室合計で最大2,000件 |
| 見学日程 | `id` | ○ | 同じ研究室内で重複しないID |
| 見学日程 | `date` | ○ | `1900-01-01`〜`2100-12-31`内の実在する日付`YYYY-MM-DD` |
| 見学日程 | `start` | ○ | 24時間表記`HH:mm` |
| 見学日程 | `end` | ○ | 終了時刻`HH:mm`（同日の開始より後）、または終了未定を表す空文字`""` |
| 見学日程 | `location` | 任意 | 会場。200文字以内 |
| 見学日程 | `note` | 任意 | 注意事項など。2,000文字以内 |
| 見学日程 | `reservationRequired` | 任意 | 予約が必要なら`true`。省略時は`false` |

IDは半角英数字・`_`・`-`の1〜64文字です。参加候補は「研究室ID + 見学日程ID」で識別するため、予定を更新しても同じ見学のIDは維持してください。別の見学に同じIDを再利用すると、以前の候補と同じものとして扱われます。

`end: ""`の予定は、カレンダー上では開始から1時間の仮枠を確保し、「終了未定」ラベル・破線・斜線で表示します。一覧と詳細でも終了未定と表示し、実際の終了時刻を補うことはありません。候補の重複確認はこの1時間の仮枠を使います。実際には1時間を超える場合もあるため、終了時刻は配布元へ確認してください。ICS出力にも「終了未定」と明記し、1時間の仮枠（`DURATION:PT1H`）として書き出します。`end`自体の省略や`null`には対応しません。

日程は日本での開催を想定した日付・時刻で表示します。終了時刻が確定している日をまたぐ予定は日ごとに分けてください。`url`は`https://`で始まるURLのみ受け付け、認証情報・空白・バックスラッシュを含むものは受け付けません。文字列はHTMLとして実行せず、テキストとして表示します。

不正なJSONや形式に合わないデータは、ファイル全体を読み込みエラーとして扱います。それまで表示していた予定は維持します。詳しい例は[架空のサンプルJSON](examples/schedule.sample.json)を参照してください。

## 検証・ビルド

```sh
npm test
npm run build
```

ビルドは`dist/`を作り直し、次の公開用ファイルだけをコピーします。

- `index.html`
- `styles.css`
- `app.js`
- `icon.svg`
- `src/schedule.mjs`
- `examples/schedule.sample.json`（架空データ）

任意のJSONや`private/`などをまとめてコピーする処理はありません。実データを公開用ファイルの内容に書き込まないでください。

## GitHub Pagesで公開する

1. このプロジェクトを[samiosu/kenkyuusitu_calender](https://github.com/samiosu/kenkyuusitu_calender)の`main`ブランチへ反映します。
2. リポジトリの**Settings → Pages → Build and deployment → Source**で**GitHub Actions**を選びます。
3. `main`へのpush、または**Actions → Deploy GitHub Pages → Run workflow**で公開処理を実行します。
4. Actionsが成功したら、Pages設定画面またはデプロイ結果に表示されたURLを開きます。

標準の公開URLは <https://samiosu.github.io/kenkyuusitu_calender/> です。カスタムドメインなどの設定によって変わる場合があります。リポジトリ名の下のパスでも動くよう、ページ内のファイル参照は相対パスです。

ワークフローはテスト後にビルドし、`dist/`だけをPagesの成果物としてアップロードします。実データのJSONをリポジトリへ追加する必要はありません。公開されるリポジトリのファイル・コミット履歴と、サイトの配信ファイルはそれぞれ確認してください。
